# TrainGuard 全面升级实施计划

## 目标与契约

完成“训练 → 保存 → 故障检测 → 清理 → 验证候选 → 恢复 → 正确性比较 → 实验报告”的闭环。沿用固定 world size、同设备同软件环境的精确恢复契约。开发在现有独立工作目录执行；先添加失败用例，再实现，每个阶段保存验收证据，最后整体独立审查。

依据：[升级评估](../analysis/upgrade-assessment-2026-09-25.md)。本计划扩展该评估的最小交付范围。

## 全局约束

- 保留已有运行、报告与历史；默认不清理检查点。
- 未提交、损坏、版本不兼容的候选不得加载；保留策略至少保留两个有效版本。
- 后台保存最多一个在途请求；完成协调使用独立 Gloo 通信组。
- 完成结论必须同时具有严格摘要、全部 rank 完成记录和完整有效步骤证据。
- CUDA、FSDP2、多节点、对象存储和主机断电结论必须来自相应环境实测。
- 本机不能完成的硬件验收标为待验收，并提供可执行入口，不计入已通过结果。

## 审查重点

1. 控制器异常发生在创建进程后、记录 PID 前：工作组必须释放。
2. 一个 rank 上传未完成或失败：全部 rank 不得提前提交或进入不同通信路径。
3. 删除中断／最新候选损坏：恢复仍保留完整回退版本。
4. 实验中断／代码配置变化：续跑不得重复统计或拼接不兼容数据。
5. 数据预取、梯度累积、AMP 跳过更新：实际消耗与优化器更新分别恢复。
