# TrainGuard 0.2 升级验收

日期：2026-09-26。实施计划：[全面升级](../plans/full-upgrade-2026-09-26.md)。本报告将在整体验收后补齐提交、实际实验与审查证据。

## 已实现

严格完成证据与异常清理；异步提前提交和超时协调；分阶段保存与恢复计量；可重试保留策略；实验续跑；JSONL 数据、确定性 shuffle/crop、预取与梯度累积；CPU BF16；CUDA DDP/FSDP2 与 FP16 scaler 代码；闭环验收入口、存储微基准与检查点预算估计；PyTorch 2.14 与格式 2。

## 必须区分的门槛

本机没有 CUDA。实卡 DDP/FSDP2、真实多节点调度／fencing、对象存储事务、断电耐久性和专用主机性能结论尚未完成。CUDA 代码不能因 CPU 测试通过而计为实卡通过。多节点与对象存储控制仍需根据选定环境实施。

JSONL 样例与测试 token 行是接口验收夹具，不代表已验证真实语料上的训练效果。支持确定性 map-style 适配器；任意第三方增强／Iterable 数据状态未纳入此契约。

历史运行保留原件。格式 1／旧运行 schema 与源码、依赖变化会被拒绝；回放使用记录的历史源码和运行时，不能改 manifest 冒充迁移。
