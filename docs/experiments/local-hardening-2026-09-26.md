# 本机检查点边界与提交计量复验（0.2.1）

日期：2026-09-26。基线 `9c55e00`／0.2.0；升级实现 `8f75ad8`／0.2.1。两次测量都在同一台 macOS 26.5.1 arm64 主机、同一 PyTorch 2.14.0／Python 3.12.12 与本地文件系统上完成；各自的源码指纹和全部原始值见 [证据 JSON](local-hardening-2026-09-26.json)。两次运行开始时工作目录均干净。

## 修复与契约

1. 检查点根目录为符号链接时，创建候选、选择候选、提交与保留清理均拒绝继续。回归用例在运行目录外放置有效检查点，确认不会沿链接读取或删除该目录。
2. 配置了 `max_retained_bytes` 却未启用 `keep_last_k` 时，启动前拒绝配置，避免预算看似生效但实际未清理。
3. 提交时每个 DCP payload 只完整读取并计算 SHA-256 一次。读取前后核对设备、inode、大小及修改／状态时间；发布 manifest 与 `COMMITTED` 后复核二者内容、全部文件名单和身份。发布中载荷改变会失败，恢复选择与加载前仍重新逐文件验哈希。未改变格式 2 的 manifest 结构与完整性判定。

符号链接检查覆盖常规误配置与受控运行目录；不能将路径检查视为防御恶意并发替换目录的隔离机制。多租户不可信目录需要基于目录描述符和存储服务权限另行设计。

## 提交阶段计量

数字是 `hash_commit_seconds` 的 3 次原始值和中位数，单位秒。它包含清单、校验、目录同步与提交发布，不包含 DCP 保存、训练或恢复。

| 载荷 | 模式 | 0.2.0 原始值 | 0.2.0 中位数 | 0.2.1 原始值 | 0.2.1 中位数 |
| ---: | --- | --- | ---: | --- | ---: |
| 64 MiB | sync | 0.0581, 0.0606, 0.0523 | 0.0581 | 0.0263, 0.0269, 0.0260 | 0.0263 |
| 64 MiB | async | 0.0523, 0.0529, 0.0524 | 0.0524 | 0.0267, 0.0261, 0.0263 | 0.0263 |
| 256 MiB | sync | 0.1921, 0.2117, 0.2069 | 0.2069 | 0.0972, 0.0977, 0.0980 | 0.0977 |
| 256 MiB | async | 0.1984, 0.1982, 0.2121 | 0.1984 | 0.1022, 0.0971, 0.1053 | 0.1022 |

本机这一阶段约减半，与读取次数从两次变一次相符。测量仅 3 次、宿主机和缓存未隔离，不能据此宣称稳定的整体训练吞吐收益或远程存储收益。专用主机上的双批次基准仍按 [既定门槛](../analysis/infrastructure-acceptance-2026-09-26.md) 执行。
