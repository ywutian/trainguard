# 两种检查点规模的 CPU 实验

本机日期：2026-09-25（America/Los_Angeles）。每个工作负载执行 3 个模式，每种模式 1 次预热、3 次正式测量；共 24 次运行，全部通过最终状态与有效样本序列的精确校验。预热不参与中位数和范围计算。

## 环境与方法

Python 3.12.12；PyTorch 2.10.0；macOS-26.5.1-arm64-arm-64bit；10 个逻辑 CPU；两个 Gloo 工作进程，每进程 1 个训练线程，CPU、本地文件系统。

两个工作负载均为固定种子 42、3000 步、序列长度 16、每 rank 批量 2、每 100 步保存。小模型为 hidden=64、1 层；较大模型为 hidden=128、2 层。每个工作负载单独使用首个无检查点运行作为参考；正式模式顺序按轮次旋转。先完整运行小模型，再运行较大模型；实验期间未并行启动本项目测试。

训练窗口排除进程组和模型初始化，包含保存、提交及最终训练屏障。总耗时还包含启动与控制器收尾。两种口径均保留；不把保存各阶段时间相加作为总耗时。

## 解释与限制

- 在每个工作负载内，同步与异步保存的训练耗时范围均有重叠，不能认定异步保存稳定更快。无检查点运行作为训练和启动开销基线。
- 这台机器不是专用隔离主机。负载快照只能反映部分主机活动，无法控制其他进程、文件缓存或热状态；需要在稳定专用机器重复测量后形成性能结论。
- 每次正式运行启动新工作进程，保留初始训练步骤。预热准备主机和文件缓存，没有从单次训练中扣除预热步骤。
- payload 是 manifest 中列出的所有文件字节数，包含 DCP 和各 rank 状态，排除 manifest 与 COMMITTED。本次每个保存模式每次运行提交 30 个检查点。
- `writing_seconds` 记录 staging 之后、训练进程在 rank 屏障观察到完成之前的时间，包含 rank 状态写入；异步值还包含重叠训练，不能作为纯磁盘 I/O 时间。
- 本次每模式仅 3 次正式测量；较早的 5 次实验未使用本次预热协议，两者不能直接归因比较。本报告不支持 GPU、多机、断电耐久性结论。
